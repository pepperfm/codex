# Project Overview (pepperfm fork)

Этот репозиторий — мой форк `openai/codex`. Я использую его как рабочую базу для своих патчей и запускаю локальный `codex-cli` из этого исходника. Поэтому любые изменения должны сохранять мои фичи и не ломать локальный запуск.

Ключевая фича форка: **Skill на всю сессию** (session skills).

## Контекст
- Это форк: `pepperfm/codex` (origin).
- Upstream — `openai/codex` (upstream).
- Локальный CLI запускается из этой папки (через `codex-here` и локальный бинарник).
  Поэтому рабочая ветка должна быть всегда в «запускаемом» состоянии.

## Запуск через codex-here
На обоих ПК используется один и тот же скрипт `~/codex-here.sh`.
Он запускает локальный бинарник из этой репы и обновляет ветку с патчами.
Следовательно, перед запуском важно, чтобы:
- `origin` указывал на мой форк;
- ветка `pepper/tui-inline-code` была актуальной и сборка проходила.

## Цель Git‑процесса
Минимизировать конфликты при запуске и синхронизации:
- На обеих машинах обновление только fast‑forward из моего форка.
- Ребейзы и конфликты решаются на одной «основной» машине.
- Итогом ребейза всегда является стабильная ветка с моими фичами.

## Ветки и роли
- `pepper/tui-inline-code` — рабочая ветка с моими патчами (её тянет `codex-here`).
- `main` в форке можно держать как «зеркало» upstream (опционально).

## Как обновляться от upstream (openai/codex)
Идея: поддерживать стабильную ветку с моими патчами и периодически ребейзить её на апстрим.

### Настройка remotes
- `origin` → мой форк (`git@github.com:pepperfm/codex.git`)
- `upstream` → оригинал (`https://github.com/openai/codex.git`)

### Обновление апстрима и сохранение фич
1) На основной машине (где разрешаю конфликты):
   ```bash
   git fetch upstream --prune
   git checkout pepper/tui-inline-code
   git rebase --autostash upstream/main
   # решаю конфликты, проверяю, что мои фичи и Personality не сломались
   git push --force-with-lease origin pepper/tui-inline-code
   ```

2) На обеих машинах (без конфликтов):
   ```bash
   git fetch origin --prune
   git checkout pepper/tui-inline-code
   git pull --ff-only origin pepper/tui-inline-code
   ```

### Важно при конфликте
- Не терять мои изменения (mode‑префиксы, их отображение, любые кастомные фичи).
- Не ломать фичу `Personality` и связанный UI.
- Сохранять доступность команд `/mode` и `/personality`.
- После ребейза всегда проверять сборку и тесты в `codex-rs`.

## Опционально: зеркалить upstream в `main`
Если хочу держать чистую базу:
```bash
git fetch upstream --prune
git checkout main
git reset --hard upstream/main
git push --force-with-lease origin main
```
Это упрощает сравнения и подготовку ребейзов.

## Почему это важно
Этот форк — рабочая версия CLI: я запускаю Codex именно из неё. Поэтому стабильность важнее «чистоты» истории, а ребейзы выполняются только на основной машине с контролем конфликтов.
